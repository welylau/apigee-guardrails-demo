Static Guardrails (in Apigee)

                    Deterministic · no model call · ~80 ms
                

                
            

            

                

                    ⚠
                    

                        Disclaimer: custom, static rule-based implementation
                        
These Static Guardrails are a custom demo built from regex, keyword lists and JavaScript rules in Apigee. They only catch patterns they were written for, can be bypassed by paraphrasing, and are not a supported product. Use them as a fast, low-cost first layer that complements, and does not replace, official guardrail solutions such as Google Cloud Model Armor.

                    

                

                
The cheapest, fastest layer: a reusable StaticGuardrails SharedFlow built only from native Apigee policies — JSON threat limits, RegularExpressionProtection signatures and JavaScript validators — plus a JavaScript scanner in the streaming EventFlow. Known-bad patterns are stopped at the gateway before any tokens are spent on Model Armor, NeMo or Gemini.


                

                    
Profiles — Balanced (default) vs Strict

                    
Pick the profile in the Profile column (header x-static-profile, default from property profile.default). Balanced treats Static Guardrails as a high-precision first line of defence: anything ambiguous is flagged and passed on so Model Armor decides, never silently allowed.

                    

                        
SignalBalancedStrict

                        
                            
Real payloads, secrets, TW / HK IDs, threatsBlockBlock

                            
Attack quoted, discussed, or pasted in a code block for reviewFlag → Model ArmorBlock

                            
Chinese negation (不要忽略之前的規則)FlagBlock

                            
Developer mode, "show the system prompt", cloud metadata URLFlagBlock

                            
Casual profanity not aimed at anyoneFlagBlock

                            
Two weak signals (e.g. email + short URL)AllowBlock (escalation)

                        
                    

                    
Choose strict for agentic or tool-calling apps where a payload could actually execute. Individual rules can be raised or lowered without redeploying via sev.overrides=RULE:BLOCK|FLAG|LOG|OFF. On the benchmark of 249 normal prompts, balanced blocks 0 and strict blocks 21, while both block every clear-cut attack.

What it detects

                    

                        
Prompt injectionInstruction override, DAN / developer mode, system-prompt extraction, chat-template tokens; ZH / JA / VI / TH variants.

                        
Code & command injectionSQL injection, XSS, template injection, shell commands, path traversal.

                        
Secrets & PIICloud keys and tokens; Luhn-checked cards, SG NRIC/FIN, Thai ID, email.

                        
Harsh languageTiered multilingual lexicon (threats · profanity block, mild insults log) with an allow-list for false positives.

                        
Business deny-listCustom terms with BLOCK or FLAG severity, e.g. a confidential project name.

                        
Structural abuseOversized prompts, too many turns, zero-width and control-character smuggling.

                    

                


                

                    
Modes

                    
    
                        
  • Inbound: Enforce (400 before Gemini) · Monitor (log would-block, allow) · Off.
    • 
                        
  • Outbound: Enforce (cut the stream) · Redact (mask secrets/PII in-flight as [REDACTED:rule]) · Monitor · Off.
    • 
                        
  • The 400 response is sanitized — it returns the rule ID and category but never echoes the matched text.
    • 
                    

                


                

                    
Why a static layer?

                    
    
                        
  • Fast and free: about 80 ms, no external call, no per-request inspection cost.
    • 
                        
  • Explainable: every block maps to a rule ID (e.g. SG-PI-001) you can audit.
    • 
                        
  • Tunable without redeploys: word lists and limits live in an environment property set.
    • 
                        
  • Complements ML layers: Model Armor and NeMo catch the paraphrased attacks regex can't.
    •

Google Cloud Model Armor

                    Managed service · Security & AI safety
                

                
            

            

                
A Google Cloud service that enhances the security and safety of AI applications by proactively screening LLM prompts and responses. Whether AI runs on Google Cloud or another cloud, it helps prevent malicious input, verify content safety, protect sensitive data, maintain compliance, and enforce AI safety and security policies consistently.


                

                    
Tuning Model Armor — the template is its "profile"

                    
Model Armor has no balanced / strict switch in this UI. Its sensitivity is set in the template used by each policy (ma-ai-gw-inbound for prompts, ma-ai-gw-outbound for responses): choose which filters run and the confidence level for each one (responsible AI categories, prompt injection & jailbreak, sensitive data protection, malicious URLs). A lower confidence threshold catches more but may block more legitimate prompts.

Templates, confidence & enforcement

                    
    
                        
  • Templates — sets of filters and thresholds; best practice is separate input and output templates.
    • 
                        
  • Confidence levels — High (fewest false positives) · Medium and above (balanced) · Low and above (most sensitive).
    • 
                        
  • Enforcement — Inspect only (log to Cloud Logging, don't block) or Inspect and block.
    • 
                    

                


                

                    
Use cases

                    
    
                        
  • Reduce leakage of sensitive IP and PII in prompts or responses.
    • 
                        
  • Protect against prompt injection and jailbreak attacks.
    • 
                        
  • Scan text in PDFs for sensitive or malicious content.
    • 
                        
  • Stop a chatbot recommending competitor solutions; filter harmful AI-generated posts.
    • 
                    

                


                

                    
How this demo uses it

                    
    
                        
  • Inbound: Apigee SanitizeUserPrompt in the ProxyEndpoint with template ma-ai-gw-inbound — blocked prompts never reach Gemini.
    • 
                        
  • Outbound: SanitizeModelResponse in the streaming EventFlow with template ma-ai-gw-outbound — cuts the SSE stream mid-flight on a violation.
    • 
                        
  • No custom code: native Apigee policies, authenticated with the proxy's service account.

NVIDIA NeMo Guardrails

                    Open source · Apache 2.0
                

                
            

            

                
An open-source toolkit for adding programmable guardrails ("rails") to LLM-based conversational applications. Rails sit between the application code and the LLM and control its output — e.g. not talking about politics, answering specific requests in a set way, following a predefined dialog path, using a particular language style, or extracting structured data.

Key benefits

                    
    
                        
  • Trustworthy, safe & secure apps — define rails that guide and safeguard conversations and keep the app away from unwanted topics.
    • 
                        
  • Secure connections — connect the LLM to models, chains, tools and other services safely.
    • 
                        
  • Controllable dialog — steer the LLM along pre-defined conversational paths and enforce standard operating procedures (e.g. authentication, support).
    • 
                        
  • LLM vulnerability protection — mechanisms against common attacks such as jailbreaks and prompt injections.
    • 
                    

                


                

                    
Five types of rails

                    

                        
Input railsApplied to user input — can reject it or alter it (mask sensitive data, rephrase).Used in this demo

                        
Dialog railsShape how the LLM is prompted and whether an action runs or a predefined response is used.

                        
Retrieval railsApplied to retrieved chunks in RAG — can reject or alter them.

                        
Execution railsApplied to the inputs and outputs of custom actions (tools) the LLM calls.

                        
Output railsApplied to LLM output — can reject it or alter it (e.g. remove sensitive data).

                    

                


                

                    
Typical use cases

                    
    
                        
  • Question answering / RAG — fact-checking and output moderation.
    • 
                        
  • Domain-specific assistants — stay on topic and follow designed flows.
    • 
                        
  • LLM endpoints — add guardrails in front of a custom LLM.
    • 
                        
  • LangChain chains — wrap chains with a guardrails layer.
    • 
                    

                


                

                    
How this demo uses it

                    
    
                        
  • Guardrails server on Cloud Run, called from the Apigee ProxyEndpoint via ServiceCallout with a Google ID token.
    • 
                        
  • Inbound only — input rails jailbreak_self_check, content_safety, topic_control (one LLM-as-judge call each).
    • 
                        
  • Outbound streaming is covered by Static Guardrails + Model Armor SMR, since ServiceCallout can't run in the EventFlow.
    • 
                        
  • Fails open on timeout/error so a cold start never blocks traffic.

🎯 Best practice: layer all three: Static → Model Armor → NeMo. Cheapest checks first.

                


                
                

                
Each of the three guardrail layers addresses AI safety, threat prevention, and compliance at different latency, cost, and intelligence boundaries. Use this guide to choose the optimal layer for your requirements or combine them into a defense-in-depth pipeline.


                
                

                    

                        

                            
                            

                                Fastest · $0 Cost
                                
Static Guardrails (in Apigee)

                            

                        

                        

                            
Choose when you need:

                            
    
                                
  • Sub-100 ms (~80 ms) gateway-native threat prevention with zero external network hops.
    • 
                                
  • Stopping deterministic attacks: SQLi/XSS, known secrets (AWS keys, GCP tokens), card numbers (Luhn check), and rigid profanity lexicons.
    • 
                                
  • In-flight streaming redaction ([REDACTED]) directly at the API gateway.
    • 
                                
  • $0 marginal cost: save LLM and API tokens on known attacks.
    • 
                            

                        

                    


                    

                        

                            
                            

                                Managed · Enterprise RAI
                                
Google Cloud Model Armor

                            

                        

                        

                            
Choose when you need:

                            
    
                                
  • Turnkey, managed Google Cloud AI security without hosting or maintaining guardrail infrastructure.
    • 
                                
  • Protection against adversarial jailbreaks (DAN), prompt injection, and multilingual toxicity (ZH, JA, VI, TH).
    • 
                                
  • Sensitive Data Protection (SDP/DLP templates) and malicious URL inspection.
    • 
                                
  • Dual-phase screening: inbound prompts (SUP) and streaming tokens (SMR via Apigee EventFlow).
    • 
                            

                        

                    


                    

                        

                            
                            

                                LLM-as-a-Judge · Topic Steerage
                                
NVIDIA NeMo Guardrails

                            

                        

                        

                            
Choose when you need:

                            
    
                                
  • Domain & topic boundaries: steering the model away from off-topic subjects (e.g. "Do not give cryptocurrency financial advice").
    • 
                                
  • Programmable conversational policies, multi-turn dialogue management, and Colang flows.
    • 
                                
  • Custom LLM-as-a-judge semantic evaluation where rigid regex or static classifiers are insufficient.
    • 
                                
  • When ~1-1.5s latency is acceptable for critical business compliance.
    •
